# OpenDelivery 项目检查与修复（2026-10-01）

本次检查覆盖 Web 五个页面、独立地图编辑器、中英文显示、后端地图与运动接口，以及任务管理、导航、仿真、定位的现有回归测试。在工作区已有日志功能改动基础上修复，未回退原有改动。

## 已修复

| 范围 | 问题与修复 |
| --- | --- |
| 日志页布局 | 窄屏及英文状态文案撑破页面；允许工具栏与标题换行，约束内容和面板最小宽度，中等桌面宽度改为两列。 |
| ROS 页面布局 | 节点卡片固定 280px 最小宽度撑破 320px 屏幕；卡片最小宽度不超过容器，卡片标题可换行。 |
| 手机监控页 | 重定位及遥控排在地图前、导航占据较多高度；地图优先，导航改为三列，顶部为机器人状态入口留出空间。 |
| 状态弹层与 CSS | 英文上线按钮越界；状态行支持换行。修正快捷机器人按钮外游离的 CSS 声明，恢复相关选择器解析。 |
| 监控切图 | 旧地图请求晚返回或失败时覆盖/清空新地图；使用请求序号过滤旧响应，地图点位及语义图片同样校验所属请求。建图数据返回时再次校验当前模式及机器人。 |
| 编辑器坐标 | 忽略 YAML origin 的旋转角；世界坐标、像素坐标转换及点位方向均应用原点旋转。 |
| 编辑器加载 | 语义图解码后及异常分支未过滤过期请求；补齐校验。重载同名地图也检查未保存修改，取消切图时恢复下拉选项，刷新页面提示未保存修改。 |
| 编辑器保存 | 保存途中继续编辑或切图可把未上传内容误标为已保存；保存时锁定编辑区域、切图、关闭、撤销和重复提交，失败后保留待保存内容。 |
| 参数页 | 读取失败后仍可提交旧值，旧保存响应可能覆盖新机器人；读取成功才启用表单，并校验请求序号和机器人 ID。详情页后台刷新保留用户正在填写的参数。 |
| 浏览器缓存 | 缓存格式损坏、存储不可用或写入超限会中断操作；侧栏、操作日志和聊天会话均增加容错。 |
| 语言与输入 | 用户聊天原文不再自动翻译；中文输入法确认候选词时不触发发送；Canvas 文本测量与绘制使用相同翻译，避免英文标签背景尺寸错误。 |
| 聊天任务状态 | 轮询到时后清空状态，像是已经完成；轮询超时明确报错，失败任务没有结果时也显示失败。 |
| 地图上传 | 仅凭 data URL 类型接受其他图片格式，栅格可改变尺寸，截断 PGM 可通过校验；验证真实格式、灰度模式、完整像素及原有尺寸，失败时不写文件。 |
| 运动接口 | NaN、Infinity 可绕过速度范围检查，非法点位可能写入缓存；速度、持续时间、位姿和点位均校验有限数值，非法请求返回 HTTP 400。 |
| 导航兼容接口 | 导航辅助子进程在目标被接受后调用 logging，却没有导入该模块；补齐导入并执行生成脚本的成功分支回归，避免任务已接受却向 Web 报错。 |
| 只读 ROS 查询 | 查询文本被直接放入 shell；解析为参数后逐个转义，shell 操作符及命令替换作为普通参数传递。 |

## 验证结果

- 后端：168 项 unittest 通过，包含地图格式、尺寸、有限数值、HTTP 400、导航辅助脚本和查询参数转义的新回归测试。
- ROS Python：导航任务、假电梯、机器人几何、真值定位，共 52 项 pytest 通过。
- C++：已有任务管理器乘梯计划测试 3 项、重定位核心测试 7 项通过；使用现有构建产物。
- JavaScript：日志解析的 9 个断言，以及旋转坐标、缓存容错、地图请求乱序/失败和参数读取失败的 5 项回归验证通过。
- 浏览器：320、390、768、1024、1280、1440px × 五个页面 × 中英文，共 60 组布局无页面横向溢出；英文状态弹层、参数刷新、输入法 Enter、聊天原文和语言恢复、同名地图重载与保存失败保护通过，浏览器未记录 JavaScript 错误。
- 弹窗：地图编辑器 320/390/768px，离线回放 320/390/768/1440px，无页面横向溢出或按钮越界；实际读取已有 bag（2307 个位姿样本），暂停回放后验证。
- JavaScript 语法、后端及相关 ROS Python 编译、启动 shell 语法和 `git diff --check` 通过。

运行中的 Web 栈可通过 `web/tests/browser_regression.py` 复查；需要 agent-browser，机器人缓存中有 robot1 且至少有一张已保存地图。可通过 `AGENT_BROWSER_BIN` 和 `OPEN_DELIVERY_WEB_URL` 指定程序与页面地址。浏览器测试仅在临时画布上编辑并放弃修改，不保存地图、不发送机器人指令。

本次没有执行实体机运动、真实电梯或在线机器人跨层导航联调；不能由这些测试推断硬件闭环已经通过。后端 Python 修改需要重新启动后端进程生效，前端刷新即可载入。
